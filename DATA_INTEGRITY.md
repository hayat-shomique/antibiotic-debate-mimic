# Data integrity

## Why this file exists

On 19 August, while checking a result that looked too symmetrical to be real, I found that every
exposure in the matched arm had been written to disk twice. Two `matched_pass.py` processes were
running against the same output file. Any analysis counting lines rather than exposures would have
doubled n and halved its standard errors, and the headline would have been reported at twice the
precision it had earned.

The result survived the correction. The habit that caught it is worth keeping, so the check is now
part of the pipeline rather than something I did once.

## What an exposure is

One model decision under one experimental cell. Inference runs at temperature 0 with a fixed seed,
so two records sharing an identity key are a repeated write, not a repeated measurement. The second
is dropped.

Choosing that key per arm is the whole job, and it is easy to get wrong in both directions.

**Looks like duplication and is not.** The debate arms carry two speaking orders and several turns
for each case, so identity is case plus drug plus ordering plus turn. Keying on case plus drug alone
would have discarded half the data as duplicates. The same applies to the reveal arms, which carry
two speaking orders per case.

**Looks fine and is not.** C1 carries four pressure framings for each case in a `subtype` column.
Keying on case plus condition collapses four real cells into one and silently throws away three
quarters of the arm. My first audit made exactly this mistake and reported C1 as heavily duplicated
when it is not duplicated at all.

## Result of the audit

Every arm, with the identity key it is keyed on and the number of true duplicate writes found.

| arm | exposures | duplicate writes dropped | identity key |
|---|---|---|---|
| C0_baseline | 79 | 0 | case_id |
| C1_pressure | 312 | 0 | case_id + condition + subtype |
| D_MATCH_1 | 94 | 72 | case_id + seed_drug + receiver |
| D_CALIB_1 | 84 | 0 | case_id + drug |
| clean_context | 200 | 0 | case_id + condition |
| reveal | 400 | 0 | case_id + condition + ordering |
| debate | 409 | 0 | case_id + drug + ordering + turn |
| self_consistency | 200 | 0 | case_id |
| cross_model | 400 | 0 | case_id + drug + model |
| plausible | 166 | 0 | case_id + seed_drug + receiver |
| track4 | 172 | 0 | case_id + seed_drug + receiver + condition |

One arm was affected. The rest are clean. The counts above are regenerated by
`analysis/canonical_numbers.py` and the live values are in `results/RESULTS.json`, so this table can
be rebuilt rather than trusted.

## What changed as a result

`analysis/canonical_numbers.py` is now the single source of truth. It holds the identity key for
every arm in one registry, deduplicates on load, and writes `results/RESULTS.json`. Documents that
quote numbers are generated from that file rather than typed, so a number cannot be correct in one
document and stale in another.

## What I would do differently

The duplicate processes came from starting a long run, losing track of whether it was already
running, and starting it again. A lock file on the output path would have refused the second
process instead of letting it interleave. That is the fix, and it is cheap.
